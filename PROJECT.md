# Куда поступить: колледжи СПб

> Этот файл написан для нового сеанса Claude (например, Claude Code), который ничего не помнит о проекте. Прочитай его целиком перед любыми правками.

## О проекте

Сайт для школьников после 9 класса в Санкт-Петербурге. Человек вводит средний балл аттестата и ближайшее метро, выбирает профессию, листает карточки колледжей в стиле Tinder (вправо: нравится, влево: пропустить), а потом сравнивает выбранные колледжи по цене, проходному баллу, времени в пути и качеству образования.

Идея владельца: человек сам выбирает и сравнивает, а сайт делает это быстро и удобно. Рекомендации и фильтры по предпочтениям не навязываем.

Сейчас это рабочий прототип в одном файле `index.html` без сервера и базы данных. Опубликован на GitHub Pages (репозиторий `Find-my-college-`), друзья его уже видели: сказали, что выглядит круто, но пока сыро.

## Главные правила

1. **Не придумывай данные.** Почти все цифры в базе (цены, проходные баллы, метро, оценки, описания, названия некоторых колледжей) сейчас демо и выдуманы. Перед показом людям как настоящего сервиса их нужно заменить проверенными данными с официальных сайтов колледжей и приёмных комиссий. Пока этого не сделано, на сайте должна быть пометка «демо».
2. **Аудитория в основном несовершеннолетняя.** Не собирай и не храни личные данные и геопозицию. Выбор района или станции метро вручную лучше, чем точная геолокация. Любая реклама и аналитика должны учитывать ограничения для детей.
3. **Файл для GitHub Pages должен называться `index.html`** и лежать в корне репозитория, иначе показывается README.
4. Баллы и цены меняются каждый год. Всегда указывай, за какой год данные.

## Структура текущего `index.html`

Всё в одном файле: стили в `<style>`, данные и логика в `<script>`.

### Данные (в начале скрипта)

- `C`: колледжи. Формат строки: `[название, метро, x, y, оценка_качества, описание]`. Координаты x и y условные (километры, центр города примерно в нуле), нужны только для расчёта времени в пути.
- `H`: ближайшие к дому станции метро (плюс «Петергоф (электричка)») с такими же условными координатами.
- `tmin(колледж)`: время в пути в минутах = `12 + расстояние по прямой × 2.2`. Это грубая оценка, не реальный маршрут.
- `P`: 8 профессий. Поля: название `n`, иконка `e`, градиент `g`, название специальности `s`, короткое описание `d`.
- `O`: предложения «профессия в колледже». Формат: `[индекс_профессии, индекс_колледжа, проходной_балл_прошлого_года, бюджет(1/0), цена_в_год, примечание]`. Примечания `M` (медсправка) и `D` (вступительное испытание по рисунку) заданы константами.
- `PI`: подробные тексты профессий для боковой панели: «что делает», «почему может подойти», «что важно знать».

### Состояние `S`

Поля: `v` (экран: `score`, `prof`, `cards`, `fav`), `score`, `home`, `p` (выбранная профессия), `sw` (история свайпов для кнопки «Вернуть»), `fav` (индексы избранных предложений из `O`), `all` (показывать все колледжи, по умолчанию `true`), `pv` (профессия, открытая в боковой панели), `tab` (вкладка профессии в сравнении), `sort` (способ сортировки), `na` (временно отключает анимации при перерисовке).

### Функции

- `render()`: перерисовывает всё приложение через `innerHTML`.
- `hdr()`: три вкладки наверху: «Балл и метро», «Профессии», «Сравнение».
- `card()`, `back()`, `bind()`, `fly()`, `act()`, `undo()`, `queue()`: карточки, их переворот, свайпы, очередь показа.
- `info()`, `selP()`: боковая панель с описанием профессии (справа на ПК, шторка снизу на телефоне).
- `favView()`: экран сравнения. Группирует по профессиям, считает «лучший для вас», рисует полоски и раскрывающийся текст.
- `delCard()`: удаление колледжа из сравнения с анимацией.
- `chk()`: проверка введённого балла (от 3 до 5, не больше двух знаков после запятой).

### Устаревший код (можно удалить)

`C0`, `O0`, `hdrOld`, `infoOld`, `extraOld`, `delCard0`: остатки старых версий, не используются.

## Что уже реализовано и согласовано с владельцем

- Балл не скрывает колледжи. Показываются все колледжи профессии, сначала те, куда балл проходит, потом остальные. Шансы указаны на карточке («Высокие шансы», «Шансы средние», «Не хватает 0,45»). Есть необязательная галочка «только где проходит мой балл».
- Три кликабельные вкладки вместо стрелок и точек.
- Тап по плитке профессии ведёт сразу к колледжам. Кнопка ℹ️ в углу плитки открывает подробное описание.
- Кнопка «↩ Вернуть» под карточкой. Тап по карточке или кнопка «ⓘ Подробнее о колледже» переворачивает её.
- Сравнение: колонки по профессиям с переключателем вкладок. Полоски по четырём параметрам, лучшие значения зелёные, раскрывающийся текст «Подробнее», удаление с анимацией.
- Сортировка «Лучший колледж для вас». Для каждой профессии отдельно: цена, время в пути и качество нормируются от 0 до 1, фактор «балл подходит» весит в 1,5 раза больше. Колледж не по баллу опускается ниже. Есть и другие сортировки: дешёвые, ближайшие, по качеству, проще по баллу. Веса выбраны на глаз.
- Владелец решил **не** добавлять фильтры по цене и другим предпочтениям: человек сам смотрит и выбирает.

## Известные проблемы и идеи

- Данные демо (см. главное правило 1).
- Описания профессий общие, хотят подробнее: чему учат, где работают, зарплаты (если брать цифры, то только из надёжных источников).
- Время в пути считается по условным координатам. Для реального расчёта нужны адреса колледжей, их координаты и сервис маршрутов с общественным транспортом.
- Карту обсуждали, но пока не делали.
- Код в одном файле, дальше его лучше разделить: данные в `data/colleges.json`, стили в `style.css`, логика в нескольких JS-файлах. Тогда владелец сможет править цены и баллы, не трогая код.
- Дизайн рабочий, но простой: нужны нормальные шрифты, фото колледжей, логотип.
- Нужны проверки на реальных телефонах: свайпы, переворот карточки, боковая панель.

Адреса, станции метро, проходные баллы и остальные цифры в текущей базе проверенными не считать.

## Ошибка, которой нужно избегать

Однажды вместо правки готового приложения был собран отдельный урезанный файл с «реальными» данными, часть которых была выдумана. Он не нужен и в репозиторий не входит. Всегда дорабатывай существующее приложение и честно помечай, что проверено, а что нет.

## Как запустить и опубликовать

- Локально: открой `index.html` в браузере. Отдельный сервер не нужен.
- Публикация: GitHub Pages, ветка `main`, папка корня. После изменения файла сайт обновляется через 1–2 минуты (вкладка Actions показывает сборку). Если открывается README, проверь имя файла `index.html`.
